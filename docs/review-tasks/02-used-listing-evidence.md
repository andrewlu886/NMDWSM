# 任務 2 強化二手貼文解析與價格證據

對應覆核表第 2 點。優先度 P0，尤其在宣稱「真實成交行情」或將資料用於估價之前。

## 最優先缺陷

目前取得的是經規則篩選的刊登價格，不是經核實的成交價格。如果擴充時沿用 `verified` 名稱卻沒有區分核實對象，容易讓後續估價與圖表誤認已證實成交。

## 現況證據

- `src/services/used-search.js` 的 `parsePttArticle()` 已使用 Cheerio 解析 PTT 的售價、品況及硬體欄位；不是完全沒有二手解析能力。
- 同檔 `sold()` 排除售出／保留等狀態；`parsePttArticle()` 對多個數字或不固定價格採略過。這有助避免錯價，但會漏掉多零件、多價格的貼文。
- `verified()` 設定 `verified: true` 與 `verifiedAt`，表示刊登通過現有檢查；它沒有成交憑據驗證的意義。
- `searchUsedProducts()` 回傳網址、價格、規格文字等資料；目前沒有完整的貼文抽取結果、成交證據、人工核實狀態資料表，也未見此解析路徑呼叫 Llama。

## 修改範圍

1. 定義 `listing_price` 與 `verified_transaction_price`，另存刊登狀態、觀測時間、證據來源及核實狀態。售出標記不代表原刊登金額就是成交金額。
2. 保留現有規則式解析；不規則貼文才交給現有 Ollama／Llama 3.1 輔助抽取。限制輸入長度、輸出 JSON schema、逾時及重試次數。
3. 每個商品分別保存完整型號、容量／尾碼、刊登價格、品況、使用時間、保固敘述、來源 ID 與證據片段；不確定欄位用 null，不讓模型補猜。
4. 程式核對價格是否出現在原文、型號是否有文字依據、單件或整組售價是否明確。多個商品無法可靠對應價格時進待覆核區，不進可用行情。
5. 貼文內容只當資料，不接受其中要求呼叫工具、改規則或傳送資訊的指令。抽取模型不執行查價或估價工具。
6. 以平台／貼文 ID／商品序號與內容版本去重，保留更新和下架狀態；經核實的成交價另設證據與人工核實紀錄。避免保留無關個資。

## 驗收條件

- 固定測試集涵蓋單件、多件、整組、議價、換物、已售出、保固日期、電話數字、運費與訂金，避免將無關數字當售價。
- 14400／14400F、12700／12700K／KF、顯卡容量與顏色不同時不合併。
- 沒有成交證據的資料一律不能進成交價格統計；`verified` 舊資料遷移後仍只表示刊登檢查通過。
- 模型無法使用、輸出 JSON 損壞或抽取衝突時，保留明確失敗／待覆核狀態，不生成假資料。
- 測試來源先固定為公開樣本；新增爬取範圍前確認來源存取限制，不繞過登入與封鎖。

## 依賴與交付

先交付價格種類與證據契約，再供任務 1、3、4 共用。不能把蒐集更多刊登資料視為已完成成交價驗證。
