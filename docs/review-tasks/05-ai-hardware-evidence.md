# 任務 5 補齊 AI 硬體建議依據與回饋核實

對應覆核表第 5 點。優先度 P0：先避免無資料時做出肯定結論，再擴充複雜諮詢。

## 最優先缺陷

目前已有 AI，但缺少足以支持完整相容性與瓶頸結論的結構化規格及驗證服務。語言模型回答流暢，不代表插槽、BIOS、記憶體規格、機殼尺寸或供電已被核實。不能把商品推薦分數當作相容性驗證或精確瓶頸百分比。

## 現況證據

- `public/AiService.js` 已接入預設 `llama3.1:8b` 與 `gemma3:4b`、工具呼叫及圖片辨識；覆核表左欄「未導入 AI」與現況不符。
- `src/services/recommendation.js` 的 `rankRecommendations()` 以 CPU／GPU 分數、RAM、OS、價格等排序，`requiredHardware` 核對商品描述；沒有完整零件相容性規則引擎。
- `public/psu-flow.js` 依功耗資料與選項計算電源建議，不能替代完整配置相容性驗證。
- `reports/cpu-power-audit.md` 的本次盤點：174 個 CPU 型號中 81 個缺少功耗紀錄，包含 71 個已有圖片的型號。缺功耗不能用同系列猜測；i7-14700 已另由補充檔提供資料。
- `docs/cpu-auto-crop-experiment.md` 記錄 i5-14400 圖片裁切可改善 Gemma 候選，但 OCR 尚未核對通過，故未接入正式流程。不得把此實驗寫成已完成的辨識改良。
- 現行程式與資料庫未見完整的回饋提交、人工覆核、版本發佈及回退流程。

## 修改範圍

1. 建立統一規格來源：完整型號、CPU／主板插槽、晶片組及 BIOS 支援、RAM 世代、機殼／顯卡／散熱器尺寸、功耗與電源接頭；每欄保留來源、核實日期與缺漏狀態。
2. 先補 CPU 功耗盤點的高頻型號，再擴充其他規格；使用原廠資料核實。PL2／PPT 與標稱 TDP 分開，電源建議瓦數不能當 CPU 功耗。
3. 建立可測試的相容性判斷 API，結果至少區分「符合已檢查條件」「不相容」「資料不足」。缺 BIOS 或尺寸等關鍵欄位時列出待確認項，不能宣稱整套相容。
4. 瓶頸分析先詢問用途、解析度及目標效能；有可追溯基準測試才能提供量化比較。無資料時給定性限制與待補資料，不生成精確百分比。
5. 新增回饋表單，保存結果 ID、涉及型號、問題類別與必要證據；人工覆核後才能變更規格或參數。每次變更記錄前後值、審核依據、版本與回退方式。

## 驗收條件

- 固定案例涵蓋插槽不符、DDR 世代不符、BIOS 未知、顯卡過長、散熱器過高、供電接頭不足及缺功耗。
- 未知欄位一律保持未知；資料充足才輸出對應範圍的判斷，不以商品描述提及某 CPU 就推定完整配置相容。
- 使用者回饋不直接修改知識、模型權重或估價參數；未核實及惡意內容不影響正式結果。
- 回饋改動後能追溯並回退；不把調整資料表描述成已重新訓練 AI 模型。

## 邊界與依賴

可先獨立完成缺資料提示與功耗補齊；估價／推薦參數回饋需要任務 2、3 的價格與版本證據。完整相容性和效能評估需另外蒐集規格，不以調整提示詞代替資料建置。
