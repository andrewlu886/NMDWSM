# 商品狀態與定期清理

市價查詢在回傳商品前獨立核對販售狀態。狀態有效期為 60 秒；購物通路的搜尋清單仍可快取 24 小時。商品頁的明確可售證據優先於搜尋清單，已缺貨、下架的項目不回傳。購物通路庫存不明時，仍在搜尋清單內的商品保留並標示「庫存未確認」；二手刊登未核對通過時略過。PChome 多規格價格衝突或無有效價格時隱藏，避免沿用不對應的舊價。

PChome 核對商品 API 的販售狀態、數量與可售規格價格；Momo 核對商品頁的庫存 metadata；欣亞核對相符商品識別碼的購物車按鈕及缺貨狀態。Yahoo 購物與 Newegg 以相符商品的 Product/Offer 證據核對。露天核對商品 API 庫存、截止時間與單一價格。PTT、旋轉拍賣、Yahoo 拍賣沿用各自的詳細頁核對；PTT 僅能確認刊登未標示售出，不能證明賣家實際持有庫存。PTT 整批核對上限 25 秒，到期取消後續請求，已通過核對的刊登仍可回傳，其餘列為核對失敗。

商品狀態包括 `available`、`unavailable`、`unknown`，保存判斷原因、核對時間、最近查詢時間與下次檢查時間。隱藏項目從商品搜尋快取移除，但保留最近七天的待核對紀錄，因此相同網址恢復、補貨或出現新的有效刊登都可以再次收錄。

伺服器啟動十秒後檢查到期工作；每分鐘檢查排程，工作不重疊：

- 每 30 分鐘核對最近七天的商品，單輪最多 100 筆，較早到期者優先；二手來源透過原有 gateway 重新查詢，單輪最多十組。
- 每六小時重新搜尋最近七天熱門的最多 50 組關鍵字與通路組合。維護任務不增加人氣或延長使用者的最近查詢時間。
- 核對最多四個並行請求，每個 HTTP 請求七秒、每批二十秒；無法及時核對的商品暫時隱藏。來源限流或驗證阻擋後，核對暫停五分鐘。

歷史結果保存當時價格，不直接提供舊商品連結；按「重新查詢」後才能取得經當前核對的連結。

狀態以原子檔案替換保存到 `.cache/market-lifecycle-v1.json`，可用 `MARKET_STATE_PATH` 指定持久磁碟路徑。**Render 免費執行個體的本機磁碟不是永久儲存，重新部署或替換執行個體可能清除狀態；休眠時也不執行排程。** 狀態檔存在時會恢復並補跑；不存在時從新查詢重建，舊商品仍須核對才能回傳。若要跨重新部署保留完整七天紀錄，需將該路徑配置於持久磁碟或另接持久資料庫。

核對測試：`node --test test/market-lifecycle.test.js test/used-search.test.js test/market-page.test.js`。
